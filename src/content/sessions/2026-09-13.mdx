## What the exit test actually measured

The criterion was written into the plan three weeks ago and never attempted: **can you finish a
random medium in 25 minutes, narrated?** Narration had stood at zero for every problem on the
board, and [the item carrying it](/open#timed-and-narrated-committed-day-one-never-once-done) had
spent five sessions recording that the gap was a missing *mechanism* rather than a missing
intention.

| Criterion | Result |
|---|---|
| Under 25 minutes | **20 min** |
| Optimal solution | **Yes** — O(n) time, O(1) extra space |
| Narrated throughout | **Yes** |
| Tests that can fail | **Yes**, verified against the named fake |

The mechanism that worked is the same shape as the one that fixed timing, and worth stating because
it generalises: **narration stopped being a step to remember mid-solve and became the thing under
test.** *Start the clock before reading* worked for the same reason — it is a step you cannot reach
and skip. "Speak while typing" never worked because it is a description of the goal.

## Why one instance closes one item and not the other

Two items were candidates for closing today and only one did, which is the distinction worth
keeping.

| | What it asks | What one instance proves |
|---|---|---|
| [Timed and narrated](/open#timed-and-narrated-committed-day-one-never-once-done) | Does the **capability** exist? | **Settles it.** It had never once been demonstrated; now it has |
| [The distinguishing input](/open#distinguishing-input) | Does the **habit** hold? | **Almost nothing.** This is the same evidence that was on the board on 2 Sep, before five sessions passed without a repeat |

The second item said *"one instance is not a habit"* on 2 Sep and stayed open on exactly that
reasoning. Closing it today, on a good day, would be applying a weaker standard because the result
was pleasant — and the whole value of this board is that it does not do that.

## The decision, and the thing it is exposed to

Phase 2 starts tomorrow. The argument is short: **phase 1's internals track is finished, the one
remaining gap is coding breadth, and the rewritten phase 2 is a breadth track** — so extending
phase 1 would mean running phase 2 under a different name for a week.

What that commits to is a weekday split of **40 coding / 50 internals**, with coding as a
first-class track rather than maintenance, and three per-problem disciplines that are — as of
today — all three demonstrated rather than aspirational.

**The failure mode is not the schedule.** Phase 1's coding track was first-class on paper too, and
produced [one topic area out of eleven](/open#coverage-every-problem-inside-topic-1) because
internals kept winning the block. Phase 3 assumes this breadth exists: its LRU problem needs linked
lists, which start tomorrow and have never been touched.

> **A date slip is absorbed by the 12–16 week runway. A breadth slip is absorbed by nothing.**

## One number not carried over

The checkpoint's inputs table records Saturday's build block as *"six categories from 259
diagnostics."* [Section 18](/internals#18-swift-6-strict-concurrency-on-a-real-target) says **five**,
which is what the day-13 addendum enumerated and named — global mutable state, genuinely
non-Sendable types, framework isolation, main-actor initialisers, and storage that was never needed.

No sixth category is named anywhere, so five stands until one is. The likely source of the six is
the lab's inspector, which has **six tabs** because `@unchecked Sendable` is included as the
*tempting wrong fix* for category 2 rather than as a category of its own. Recorded here rather than
silently reconciled, because a count that drifts without an enumeration behind it is exactly the
kind of number this site was rebuilt to stop hand-maintaining.
