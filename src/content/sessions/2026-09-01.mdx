## The artifact

[**lc424-window.html**](/artifacts/lc424-window.html) — a standalone interactive stepper, kept in the
repo under `public/artifacts/`. It runs the real algorithm rather than a hardcoded table, so what it
shows is what the code does. Adjustable `k` from 0 to 3, predict-then-reveal at each step, and a
header reporting the answer and the total `left`-movements for the selected `k` — which is where the
amortised measurement came from.

Worth generalising. The difference from a scrubbable trace is that it makes you **commit** before it
reveals, which is the difference between clarity and recall.

## The cold-recall check, before anything else next session

Blank editor, five minutes: **write the shrink condition for 424, and state why `maxFreq` is not
recomputed inside the loop.**

If it comes out clean, today's method is validated and becomes the default. If it does not, the
clarity did not convert to recall and the trace-then-rewrite loop needs another pass. Either result
is worth having; only skipping it wastes the day.
